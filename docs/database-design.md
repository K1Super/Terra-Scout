# Terra Scout 数据库设计

> 本文为数据库层唯一权威定义。
> 文档版本：V3.0 ｜ 更新日期：2026-09-18 ｜ 适用范围：P0 单机桌面版
> 基准：单一 V1 全量基线，error_code 统一 INT；自建 schema_migration 账本已废弃；
> H2 密码首启生成并持久化（D-006）；不使用 AUTO_SERVER；
> `AUTO_INCREMENT` 统一为 H2 2.x 的 `GENERATED BY DEFAULT AS IDENTITY`；
> `sdk_version` 补齐版本匹配算法必需字段（D-017）。

## 1. H2 配置

数据库密码**不由 YAML 随机生成**。首次启动引导流程（D-006）：

```text
1. 启动时检查 {data-root}/config/db.properties 是否存在
2. 不存在 → SecureRandom 生成 24 字节 → Base64 → 写入 terrascout.db.password=<value>
   → 通过 AclFileAttributeView 设置仅当前用户可读写（等效 chmod 600）
3. 存在 → 读取复用
4. 首次连接时 H2 自动建库
```

```yaml
spring:
  config:
    import: "optional:file:${terrascout.data-dir}/config/db.properties"
  datasource:
    url: jdbc:h2:file:${terrascout.data-dir}/db/terrascout;DB_CLOSE_DELAY=-1
    driver-class-name: org.h2.Driver
    username: terrascout
    password: ${terrascout.db.password}
  jpa:
    hibernate:
      ddl-auto: validate
  flyway:
    enabled: true
    locations: classpath:db/migration
    baseline-on-migrate: false
```

要点：

- **不使用 `AUTO_SERVER=TRUE`**：单 JVM 进程无需混合模式，避免额外监听端口与攻击面
- `DB_CLOSE_DELAY=-1`：JVM 生命周期内保持连接池
- `baseline-on-migrate: false`：全新产品，无历史库需要 baseline
- `ddl-auto: validate`：实体与迁移强校验，任何漂移启动即失败（错误码 500006）

## 2. 迁移策略（D-005 定稿）

- **单一基线 `V1__init.sql`**：包含 P0 全部最终表结构。项目尚无任何已部署版本，不存在增量历史
- **迁移账本唯一**：Flyway 默认 `flyway_schema_history`，禁止自建迁移账本表
- 此后任何 schema 变更 = 新增 `V<n>__<描述>.sql`，编号递增，**已发布脚本永不修改**
- 所有 `error_code` 字段类型为 **INT**（6 位数字错误码，与 assets/openapi.yaml `errorCode: integer` 一致）
- `sdk_version` 表与 assets/sdk-metadata-schema.json 的 `sdkEntry` 字段一一对应（D-017），加载器直接按字段名映射（camelCase → snake_case）

## 3. V1__init.sql（完整基线）

```sql
-- ============================================================
-- Terra Scout V1__init.sql（P0 基线，唯一初始迁移）
-- 目标库：H2 2.2.x（原生模式）
-- 规则：发布后本文件不得修改，变更一律新增 V<n>__*.sql
-- ============================================================

CREATE TABLE project (
    id VARCHAR(36) PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    project_root_path VARCHAR(1024) NOT NULL,
    os_type VARCHAR(32) NOT NULL DEFAULT 'WINDOWS',
    profile_json TEXT,
    created_at BIGINT NOT NULL,
    updated_at BIGINT NOT NULL,
    CONSTRAINT uk_project_path UNIQUE (project_root_path)
);
CREATE INDEX idx_project_os ON project(os_type);

CREATE TABLE sdk_version (
    id VARCHAR(36) PRIMARY KEY,
    language VARCHAR(32) NOT NULL,
    version VARCHAR(64) NOT NULL,
    os VARCHAR(32) NOT NULL,
    arch VARCHAR(32) NOT NULL,
    download_url VARCHAR(1024) NOT NULL,
    sha256 VARCHAR(128) NOT NULL,
    size_bytes BIGINT,
    lts BOOLEAN NOT NULL DEFAULT FALSE,
    eol BOOLEAN NOT NULL DEFAULT FALSE,
    eol_date DATE,
    cve_count INT NOT NULL DEFAULT 0,
    highest_cve_severity VARCHAR(16) NOT NULL DEFAULT 'NONE',
    license VARCHAR(128),
    distribution VARCHAR(64),
    vendor VARCHAR(128),
    release_time BIGINT,
    created_at BIGINT NOT NULL,
    CONSTRAINT uk_sdk_lang_ver_os_arch UNIQUE (language, version, os, arch)
);
CREATE INDEX idx_sdk_lang ON sdk_version(language);

CREATE TABLE sdk_install_record (
    id VARCHAR(36) PRIMARY KEY,
    language VARCHAR(32) NOT NULL,
    version VARCHAR(64) NOT NULL,
    install_path VARCHAR(1024) NOT NULL,
    scope VARCHAR(16) NOT NULL DEFAULT 'PROJECT',
    project_id VARCHAR(36),
    status VARCHAR(32) NOT NULL,
    checksum VARCHAR(128),
    installed_at BIGINT NOT NULL,
    CONSTRAINT fk_install_project FOREIGN KEY (project_id) REFERENCES project(id)
);
CREATE INDEX idx_install_project ON sdk_install_record(project_id);
CREATE INDEX idx_install_scope ON sdk_install_record(scope);

CREATE TABLE task (
    id VARCHAR(36) PRIMARY KEY,
    parent_id VARCHAR(36),
    task_type VARCHAR(64) NOT NULL,
    status VARCHAR(32) NOT NULL,
    payload_json TEXT NOT NULL,
    progress DOUBLE NOT NULL DEFAULT 0,
    retry_count INT NOT NULL DEFAULT 0,
    max_retry INT NOT NULL DEFAULT 3,
    lock_owner VARCHAR(128),
    heartbeat_at BIGINT,
    error_code INT,
    error_msg TEXT,
    idempotency_key VARCHAR(64),
    created_at BIGINT NOT NULL,
    updated_at BIGINT NOT NULL,
    CONSTRAINT uk_task_idempotency UNIQUE (idempotency_key)
);
CREATE INDEX idx_task_status ON task(status);
CREATE INDEX idx_task_parent ON task(parent_id);

CREATE TABLE task_step (
    id VARCHAR(36) PRIMARY KEY,
    task_id VARCHAR(36) NOT NULL,
    step_index INT NOT NULL,
    step_name VARCHAR(128) NOT NULL,
    status VARCHAR(32) NOT NULL,
    input_json TEXT,
    output_json TEXT,
    rollback_json TEXT,
    error_code INT,
    error_msg TEXT,
    started_at BIGINT,
    finished_at BIGINT,
    retry_count INT NOT NULL DEFAULT 0,
    CONSTRAINT uk_task_step UNIQUE (task_id, step_index),
    CONSTRAINT fk_step_task FOREIGN KEY (task_id) REFERENCES task(id)
);
CREATE INDEX idx_step_task ON task_step(task_id);
CREATE INDEX idx_step_status ON task_step(status);

CREATE TABLE command_execution (
    id VARCHAR(36) PRIMARY KEY,
    project_id VARCHAR(36),
    command TEXT NOT NULL,
    args_json TEXT NOT NULL,
    work_dir VARCHAR(1024) NOT NULL,
    env_json TEXT,
    exit_code INT,
    stdout_file VARCHAR(1024),
    stderr_file VARCHAR(1024),
    status VARCHAR(32) NOT NULL,
    started_at BIGINT NOT NULL,
    finished_at BIGINT,
    CONSTRAINT fk_cmd_project FOREIGN KEY (project_id) REFERENCES project(id)
);
CREATE INDEX idx_cmd_project ON command_execution(project_id);

CREATE TABLE audit_log (
    seq BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    biz_id VARCHAR(36) NOT NULL,
    action VARCHAR(128) NOT NULL,
    target_type VARCHAR(64),
    target_id VARCHAR(36),
    before_json TEXT,
    after_json TEXT,
    result VARCHAR(32) NOT NULL,
    prev_hash VARCHAR(64),
    hash VARCHAR(64) NOT NULL DEFAULT '',
    created_at BIGINT NOT NULL
);
CREATE INDEX idx_audit_biz ON audit_log(biz_id);
CREATE INDEX idx_audit_action ON audit_log(action);
CREATE INDEX idx_audit_created ON audit_log(created_at);
CREATE INDEX idx_audit_seq ON audit_log(seq);
```

设计说明：

- **`audit_log.biz_id` 为普通索引而非唯一约束**（D-015）：一个业务 ID 产生多条审计记录是常态
- hash 链两列（`prev_hash` / `hash`）自基线即存在，无需后续迁移补列
- `sdk_install_record` 的 `scope` / `project_id` 自基线即存在，无需后续迁移补列
- `task_step` 自基线即存在，无需后续迁移补列

## 4. 表结构摘要

| 表 | 用途 | 关键约束 |
|---|---|---|
| project | 项目记录 | `uk_project_path` 根路径唯一 |
| sdk_version | SDK 版本目录（元数据） | `uk_sdk_lang_ver_os_arch` 四元唯一 |
| sdk_install_record | SDK 安装记录 | FK → project；scope 记录归属 |
| task | 任务主表 | `uk_task_idempotency` 幂等唯一 |
| task_step | 任务步骤明细 | `uk_task_step(task_id, step_index)` |
| command_execution | 命令执行记录（日志落盘） | FK → project |
| audit_log | 审计日志（hash 链防篡改） | `seq` 自增主键 |

| 表 | 字段 | 取值 |
|---|---|---|
| project | os_type | `WINDOWS`、`MACOS`、`LINUX` |
| sdk_version | language | `JAVA`、`NODE`、`PYTHON`、`GO` |
| sdk_version | os | `WINDOWS`、`MACOS`、`LINUX` |
| sdk_version | arch | `AMD64`、`ARM64` |
| sdk_version | highest_cve_severity | `NONE`、`LOW`、`MEDIUM`、`HIGH`、`CRITICAL` |
| sdk_install_record | scope | `GLOBAL`、`PROJECT` |
| sdk_install_record | status | `INSTALLING`、`SUCCESS`、`FAILED`、`ROLLED_BACK` |
| task | status | `PENDING`、`QUEUED`、`RUNNING`、`PAUSED`、`SUCCESS`、`FAILED`、`CANCELLED`、`ROLLING_BACK`、`ROLLED_BACK` |
| task | task_type | `PROJECT_ASSEMBLE`、`SDK_INSTALL`、`SDK_UNINSTALL`、`DEPENDENCY_INSTALL`、`VERIFY_PROJECT` |

> 枚举三表同步义务：本表 ↔ api-spec.md / assets/openapi.yaml 枚举 ↔ terra-scout-core 枚举类（见 SRS.md 需求基线）。

## 6. 备份策略

- **启动备份**：在 `main()` 中、Spring 上下文启动（建立第一个连接）**之前**复制 `terrascout.mv.db` → `{data-root}/db/backup/terra-scout-{yyyyMMddHHmmss}.mv.db`。此时无任何写入，文件一致性有保证

```java
public static void main(String[] args) {
    BackupRunner.runBeforeSpring();   // 复制 mv.db（尚无连接，一致性安全）
    SpringApplication.run(TerraScoutApplication.class, args);
}
```

- **运行期在线备份**：`POST /api/v1/system/backup` 使用 H2 `BACKUP TO` 语句产出一致快照
- 备份保留 7 天，清理由 cleanupExecutor 每小时执行

## 7. 迁移失败处理

- Flyway 校验失败 → 启动中止，错误码 500006
- 恢复流程：从 `{data-root}/db/backup` 还原 mv.db → 修复迁移脚本（新增 V 脚本）→ 重新启动
- Flyway 社区版无 undo：回滚 = 备份恢复；跨大版本升级前强制自动备份
